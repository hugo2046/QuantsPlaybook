# 中信（CITICS）一级行业分类接入说明

> **更新日期**：2026-09-01
> **适用范围**：`相对旋转图RRG行业轮动` 全链路（RRG / 扩散 / 信号 / ETF 暴露）
> **适配层**：`src/data_provider.py`（离线版；原 `pg_provider` 已并入）

## 1. 总览

中信一级行业与申万链路保持**逐列同构**，`classification="sw"|"zx"` 一个参数即可切换，默认值为 `"sw"`。两套成分数据在离线版均已物化进 `data/etf_rrg.duckdb`（原 PostgreSQL `local_pg_datacenter` 物化而来），运行期经 `RRGStore.get_membership` 读取，不连 PG。

- 中信一级 30 个行业：`CI005001.CI` … `CI005030.CI`，其中 `CI005029.CI` 为综合、`CI005030.CI` 为综合金融。
- 申万一级 31 个行业，仅有 `801230.SI` 综合，没有综合金融；因此研报“剔除综合、综合金融”的原文口径只有中信能完全表达。
- 个股代码保留 `.SH` / `.SZ` / `.BJ` 后缀，与 qlib 口径一致。
- 成分输出由一个共享 reader 负责查询、交易日历展开和去重，再由 SW/ZX 两个薄封装传入表名。

透传链：

```text
RRGSignalGenerator(classification=)
  ├→ fetch_rrg_dataset(classification=)
  │     └→ get_sw_industry_data | fetch_zx_industry_data
  └→ fetch_diffusion_dataset(classification=)
        └→ RRGStore.get_membership(classification=)
              └→ fetch_sw_membership | fetch_zx_membership

ETFExposureBuilder(classification=)
  └→ RRGStore.get_membership(classification=)
```

## 2. PostgreSQL 表契约

原始成分来自 PG（`local_pg_datacenter`），已一次性物化进 `data/etf_rrg.duckdb`；离线运行期只读该快照，不执行 PG 查询。

### 2.1 `sw_index_member` / `zx_index_member` — 成分归属区间

两表逐列同构，reader 只使用一级字段：

| 列 | 类型 | 含义 |
|---|---|---|
| `id` | integer | 主键，业务无关 |
| `l1_code` / `l1_name` | text | 一级行业代码 / 名称 |
| `l2_code` / `l2_name` | text | 二级行业代码 / 名称，本项目不消费 |
| `l3_code` / `l3_name` | text | 三级行业代码 / 名称，本项目不消费 |
| `code` / `name` | text | 个股代码 / 名称，含历史退市股 |
| `in_date` / `out_date` | date | 归属区间端点；`out_date IS NULL` 表示至今 |
| `is_new` | text | `Y` / `N` |

实测规模：

| 表 | 行数 | 个股数 | `in_date` 范围 | 一级行业数 | `out_date` 为空 |
|---|---:|---:|---|---:|---:|
| `sw_index_member` | 14,879 | 5,906 | 1984-05-09 ~ 2026-08-28 | 31 | 10,733 |
| `zx_index_member` | 9,489 | 5,755 | 2000-05-25 ~ 2026-08-11 | 30 | 5,497 |

`name` 映射为 drop-in 输出中的 `sec_name`；行业代码与行业名称直接取 `l1_code` / `l1_name`，不再需要中文名到 CI 代码的二次映射。

### 2.2 `zx_daily` / `zx_index_classify` — 中信行业指数

行业指数路径仍由 `fetch_zx_industry_data` 使用：`zx_daily` 与 `zx_index_classify` join 取得行业名，`_read_sql`、`_PG_CONFIG_KEY`、`_LEVEL_TEXT` 和该路径均保留。本次切换只涉及成分，不改变行业指数取数。

| 数据 | 说明 |
|---|---|
| `zx_daily` | 行业指数日线，含 `open` / `close` 等行情字段 |
| `zx_index_classify` | 行业目录，提供 `L1` 代码与名称 |

## 3. 可用窗口与覆盖率边界

| 数据 | 当前口径 | 使用边界 |
|---|---|---|
| 申万行业指数 | datacenter `get_sw_industry_data` | 健康，保留原路径 |
| 申万成分 | PG `sw_index_member` | 2015-06-30 在册 2,865 只；本项目不加同类历史守卫 |
| 中信行业指数 | PG `zx_daily` | 2014-01-02 起；2021-01-01~2026-06-04 30 个 L1 相对交易日历零缺日 |
| 中信成分 | PG `zx_index_member` | 2015-06-30 在册 1,777 只，约 64%；默认可用起点为 2019-12-02 |

`2019-12-02` 是中信成分源的全量重建日。此前覆盖不足且存在同日多一级行业归属，缺失无法由 `ffill` 修复。离线快照的中信 coverage 水位即从此日之后起算；请求早于该窗口会命中缺口并报错（离线严格），不会静默取空。

`fetch_diffusion_dataset` 会在请求起点前移 `lookback + smooth_window` 个交易日。因而扩散信号的起点也必须为前移后的日期留出中信成分安全边界；越界抛错是设计意图，不是需要软化的 warning。

## 4. 成分 reader 行为

> **离线迁移版**：成分数据已在 `data/etf_rrg.duckdb` 快照里，运行期用 §4.1 的 `RRGStore.get_membership` 读取，不连 PG。§4.1 之后的 PG reader / SQL 细节描述的是**快照生产侧**（原在线从 PG 物化成分的实现），保留供了解快照如何生成。

### 4.1 共享 reader 与两个薄封装

```python
from src.store import RRGStore

with RRGStore() as store:                    # 只读 data/etf_rrg.duckdb 离线快照
    sw = store.get_membership("2024-01-01", "2024-12-31", classification="sw")
    zx = store.get_membership("2024-01-01", "2024-12-31", classification="zx")
```

两者返回完全相同的列：

```text
[code, trade_date, industry_code]
```

底层 `_fetch_pg_index_member(table, start, end, level=1)` 只接受 `sw_index_member` / `zx_index_member` 两个白名单表名，查询条件为：

```sql
WHERE in_date <= :end
  AND (out_date IS NULL OR out_date > :start)
```

绑定参数使用 PostgreSQL `date` 类型；二级/三级字段虽然存在，但当前接口显式只支持 `level=1`。

### 4.2 半开区间、展开和去重

每条区间按 `[in_date, out_date)` 映射到 `DataFeed` 交易日历：

- `in_date` 当天包含；
- `out_date` 当天排除，下一段从同日 `in_date` 开始时不会重叠；
- `out_date IS NULL` 展开到请求日历末日；
- 使用既有 `searchsorted` + ragged-range 向量化实现，不逐日循环。

展开后按以下键排序并对 `(trade_date, code)` 保留第一条：

1. `in_date` 降序：同日冲突取最新登记；
2. `industry_code` 升序：破除相同 `in_date` 的行业并列；
3. `industry_name` 升序：终极确定性 tie-breaker。

这条去重规则同时作用于 SW 与 ZX。SW 新源在实测中存在 265 只股票同日多归属，因此不能只在中信侧保留。

### 4.3 `classification` 用法

```python
from src.generator import RRGSignalGenerator
from src.data_provider import fetch_rrg_dataset, fetch_diffusion_dataset
from src.store import RRGStore
from src.exposure import ETFExposureBuilder

gen = RRGSignalGenerator(
    start_date="2021-01-01", end_date="2026-06-04", classification="zx"
)
benchmark, industry_close, code2name = fetch_rrg_dataset(classification="zx")
close, membership, free_float_mv = fetch_diffusion_dataset(classification="zx")

with RRGStore() as store:
    cons = store.get_membership(
        "2021-01-01", "2026-06-04", classification="zx"
    )

builder = ETFExposureBuilder(
    codes, start_date="2021-01-01", end_date="2026-06-04", classification="zx"

```

信号链和暴露链必须使用同一 `classification`，否则行业代码无法对齐，优化结果可能静默为空。历史列名 `sw_code` 保持不变，但在 `classification="zx"` 时承载 `CI005xxx.CI`。

## 5. DuckDB 缓存迁移

`RRGStore` 仍保留独立的 `sw_membership` / `zx_membership` 及各自 coverage 表。由于成分源和口径已切换，切换时必须先备份 `data/etf_rrg.duckdb`，再只清空：

```sql
DELETE FROM sw_membership;
DELETE FROM sw_membership_coverage;
DELETE FROM zx_membership;
DELETE FROM zx_membership_coverage;
```

不要删除 `etf_portfolio` 或 `etf_portfolio_coverage`。清空后首次请求会从对应 PG 表重新灌入，SW/ZX 两套水位互不影响。

## 7. 固有差异与 PIT 风险

- 中信 30 个一级行业、申万 31 个一级行业，行业颗粒度不同；SW/ZX A/B 结果不能只归因于数据质量。
- 两表保留退市股历史归属，实际扩散行情由 qlib `ashares` 时点市场池与 membership 交集决定，避免生存偏差。
- `in_date` / `out_date` 是生效日，不是公告日。表中没有可用的公告日字段；按生效日做 PIT 时，追溯性重分类仍可能带来前视，这是两套 PG 成分共有的已知边界。
