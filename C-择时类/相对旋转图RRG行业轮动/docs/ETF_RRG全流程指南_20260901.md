## 0. 读之前必须知道的三件事

**① 这套代码复现的是研报，不是一个已验证有效的策略。**
西部证券研报自己写道：「超额净值在 **2021.09–2024.03** 期间持续回撤」。本项目的回测窗口从 2022-09 开始，整段落在研报承认的回撤期内。**跑出来不好看是预期内的**，不是你装错了。结论边界见 §7。

**② 用 conda base，不要用 uv。**
仓库的 uv 环境缺 `tushare` / `duckdb` / `vectorbt`，一跑就 `ModuleNotFoundError`。

**③ 必须 `cd` 到 `相对旋转图RRG行业轮动/` 再运行。**
`tests/conftest.py` 和 example 靠 `sys.path.insert` 修 import，换个目录就找不到 `src.*`。

## 1. 三步跑出第一个结果

### Step 1：进目录，设环境


`PYTHONPATH=$HOME/workspace` 是为了让 `DataFeed`（取数库，在 `~/workspace/DataFeed`）可被 import。

```bash
py -m pytest tests -q
```

预期：`232 passed`。全部用合成数据，不连任何数据库——这一步通过说明代码完好，与数据源无关。

### Step 3：生成第一个信号

```bash

g = RRGSignalGenerator(start_date='2021-01-01', end_date='2026-06-04', classification='zx')
```

预期输出类似：

```
(1311, 30)
2026-06-02    5
2026-06-03    5
2026-06-04    5
```

（列数 30 = 中信一级全部行业；`exclude` 只影响**排序时剔除谁**与等权基准篮子，不删列。

## 2. 全流程数据流

```
                    ┌──────────────── 行业指数层（§2）────────────────┐
                    │                                                │
 行业指数日线 ──┐                                                     │
 (close/open)  ├─→ fetch_rrg_dataset ─→ compute_rrg ─→ RS-Ratio/Mom ─┤
 行业等权基准 ──┘                                          │          │
                                                          ↓          │
 个股 close ────┐                                    classify_quadrant│
 个股成分 ──────┼─→ fetch_diffusion_dataset ─→ diffusion_value_weighted
 个股流通市值 ──┘                                          │          │
                                                          ↓          │
                              strategy.select_* ─→ 日频 boolean mask ─┤
                                                          │          │
                                          run_signal_backtest ───────┘
                                                          │
                    ┌──────────────── ETF 层（§3）────────┴──────────┐
                    │                                                │
 ETF 元信息 ────┐                                                    │
 ETF 日行情 ────┼─→ 候选池构建 ──┐                                    │
 ETF 季度持仓 ──┘                ├─→ build_exposure_panel → E_t dict  │
 个股成分 ──→ aggregate_industry_weights ─┘                          │
                                                          │          │
                          mask 月末采样 → score ─→ batch_optimize ────┤
                                                          ↓          │
                                          mask_listed → run_vbt_backtest
                                                          │
                                                    portfolio_stats
```

**六层职责**

| 层 | 文件 | 干什么 |
|---|---|---|
| 数据层 | `data_provider.py` | 取行业指数、个股成分、ETF 元信息/行情/持仓 |
| 缓存层 | `store.py` | DuckDB 增量缓存季度持仓与行业成分 |
| 算法层 | `factor_algo.py` | 纯函数：RRG 比率法（中心 100）+ 两版扩散指标 |
| 信号层 | `strategy.py` / `generator.py` | 三类信号 → 日频 boolean mask |
| 组合层 | `exposure.py` / `optimizer.py` | 真实持仓 → 行业暴露矩阵 E；LP 求 ETF 权重 |
| 回测层 | `backtest.py` | vectorbt 撮合 + 绩效 |

## 3. 走一遍行业指数层（研报 §2）

信号有三类，`generate()` 的第一个参数选：

| 信号 | 含义 | 需要成分股数据 |
|---|---|---|
| `quadrant` | 纯 RRG，按象限选，欧氏距离排序 | ❌ 只用行业指数 |
| `diffusion` | 纯扩散，选扩散指标最高的 top_n | ✅ |
| `diffusion_rrg` | 扩散 top_n 后剔除三/四象限（研报 §2.3） | ✅ |

**「需要成分股数据」这一列很重要**——它决定了你能回溯到多久，见 §6 的坑。

跑一个完整的行业指数层回测：

```python
import sys; sys.path.insert(0,'.'); sys.path.insert(0,'../..')
import pandas as pd
from src.generator import RRGSignalGenerator
from src.data_provider import fetch_zx_industry_data
from src.backtest import run_signal_backtest, portfolio_stats
from src.utils import month_end_dates

g = RRGSignalGenerator(start_date="2021-01-01", end_date="2026-06-04",
                       classification="zx")
mask = g.generate("diffusion_rrg", top_n=6, keep_quadrants=(1, 2))

# 研报 §2 是月末调仓；mask 是日频，采样由调用方做（generate 不内置月末逻辑）
mask_me = mask.loc[month_end_dates(mask.index)]

price = fetch_zx_industry_data("2022-09-01", "2026-06-04", fields=("close", "open"))
pf = run_signal_backtest(mask_me.loc[pd.Timestamp("2022-09-01"):], price)
print(portfolio_stats(pf))
```

`run_signal_backtest` 把 boolean mask 等权化后回测：`close` 估值、`open` 成交、`fees=3e-4`（研报单边万 3）。

## 4. 走一遍 ETF 层（研报 §3）

ETF 层是**七段链**。每段都可能出问题，所以分开看。

```python
import sys; sys.path.insert(0,'.'); sys.path.insert(0,'../..')
import pandas as pd
from src.data_provider import fetch_etf_meta, fetch_etf_daily
from src.exposure import ETFExposureBuilder
from src.store import RRGStore
from src.backtest import (build_overseas_share, build_report_universe_panel,
                          build_exposure_panel, mask_listed,
                          run_vbt_backtest, portfolio_stats)
from src.optimizer import batch_optimize
from src.generator import RRGSignalGenerator
from src.utils import month_end_dates

START, END, BT = "2021-01-01", "2026-06-04", "2022-09-01"
store = RRGStore("data/etf_rrg.duckdb")          # ① 显式锚定缓存库

# ② 候选池 + 共享行情（剔未上市 / QDII）
meta = fetch_etf_meta(only_listed=True, drop_qdii=True)
codes = sorted(meta.index)
adjclose, adjopen, amount = fetch_etf_daily(codes=codes, start_date=START,
                                            end_date=END, lookback=25)

# ③ 行业层信号 → 月末采样成打分
g = RRGSignalGenerator(start_date=START, end_date=END, classification="zx")
mask = g.generate("diffusion_rrg", top_n=6, keep_quadrants=(1, 2))
me = month_end_dates(mask.index)
score = mask.loc[me].astype(float)

# ④ 真实持仓 → 行业权重（PIT，DuckDB 增量缓存）
with ETFExposureBuilder(codes=codes, start_date=START, end_date=END,
                        store=store, classification="zx") as b:
    iw = b.build_industry_weights()
    ovs = build_overseas_share(b.load_portfolio())   # 境外占比，用于剔港股

# ⑤ 候选池（研报口径：全池 + 同指数留 20 日 ADV top1 + 剔港股）
panel = build_report_universe_panel(meta, amount, me, lookback=20,
                                    overseas_share=ovs, overseas_threshold=0.5)

# ⑥ 暴露矩阵 → LP 求权重 → 上市日防呆
expo = build_exposure_panel(panel, iw)
vd = [d for d in me if d in expo]
w = mask_listed(batch_optimize(score.loc[vd], exposures=expo, dates=vd,
                               preset="base", strict=False), meta)

# ⑦ 回测
cm = w.columns.intersection(adjclose.columns)
pf = run_vbt_backtest(w[cm].loc[BT:], adjclose[cm].loc[BT:], adjopen[cm].loc[BT:],
                      fees=3e-4, slippage=0.0, init_cash=1e7)
print(portfolio_stats(pf))
store.close()
```

### 两种候选池，选哪个

| 函数 | 口径 | 池子规模 | 何时用 |
|---|---|---|---|
| `build_report_universe_panel` | **研报 §3.1**：全池 + 同指数留 ADV top1 | 约 436 只 | **对标研报时用这个** |
| `build_dynamic_representative_panel` | 每行业按持仓主导行业选 1 只代表 | 约 30 只 | 想要小而集中的组合 |

**候选池是复现差距的主因**，两者结果差一个量级（研报 §3.7 口径）。

### 五个 optimizer 预设

| 预设 | 约束 | 出处 |
|---|---|---|
| `base` | 满仓 Σw=1，行业暴露 ≤1/k | 研报 §3.1 |
| `etf_capped` | 单 ETF ≤0.2，仓位 min(1, 0.2k)，行业 ≤1/k | 研报 §3.2 |
| `unconstrained` | 无行业上限、单 ETF ≤1、Σw≤1 | 研报 §3.3 |
| `hs300_enhanced` | 行业偏离带 \|Ew−b\| ≤ δ | 研报 §3.4 |
| `ind_free_capped` | 删行业上限 + 保留单 ETF ≤0.2 | ⚠️ **自研，研报无此设定** |

> `unconstrained` 会退化到只持 1–2 只 ETF。**这是研报的设计意图，不是 bug**——研报原文写「多数时期仅持有 1 到 2 只 ETF」。不要"修"它。

## 5. How-to

### 如何切换申万 / 中信

一个参数贯穿四层，默认 `"sw"`：

```python
RRGSignalGenerator(..., classification="zx")
ETFExposureBuilder(..., classification="zx")
```

`benchmark_exclude` 默认哨兵 `"auto"` 会按体系解析：`sw` → 剔「综合」；`zx` → 剔「综合 + 综合金融」（研报原文口径，只有中信能严格对齐）。

### 如何准备数据

离线版不取数、不预热：所有数据已物化进 `data/etf_rrg.duckdb`（约 1.1GB，已 gitignore），经百度网盘分发。首次使用：从网盘下载 `etf_rrg.duckdb` 放到 `data/` 下即可（见 `data/说明.md`）。

### 如何跑端到端冒烟

```bash
jupyter nbconvert --to notebook --execute notebook/etf_rrg.ipynb
```

notebook 覆盖：行业指数取数（读快照）→ RRG/扩散信号 → 真实持仓暴露 → LP 优化 → vbt 回测 → 3 基准对比。关注点：**`compute_rs` 的缺日 ffill 告警应为零**——行业指数实测零缺日，一旦触发说明快照或 pivot 坏了，而下游照样产出看似正常的数字。

### 关于实验脚本

原项目 `script/` 下的样本外/候选池/自研变体等实验脚本（`exp_report_universe` / `exp_oos_quadrant` / `exp_zx_diffusion_oos` / `exp_ind_free_capped` 等）**本离线迁移版未包含**。其结论对应研报 §3.7–3.10，可用 `src/` 的纯函数 + `data/etf_rrg.duckdb` 快照自行复算。

## 6. 三个需要主动核对的坑

其中缓存和数据源边界会静默影响结果，ZX 历史越界则会明确报错。

### ① 成分数据来自离线快照（原 PG 物化），注意历史覆盖边界

> 离线版：成分已物化进 `data/etf_rrg.duckdb`，经 `RRGStore.get_membership(start, end, classification=...)` 读取，不再连 PG。下面的覆盖边界（申万自 2015 连续、中信 `2019-12-02` 全量重建日）即快照 coverage 水位；请求早于该窗口会命中缺口并报错（离线严格）。

申万成分（原 PG `sw_index_member` 物化）在快照里，经 `RRGStore.get_membership(classification="sw")` 读取。该表在
2015-06-30 有 **2,865** 只在册，不再适用旧 datacenter `sw_level1_cons` 的
“2022-08 才连续”结论；申万侧没有同中信一样的 `2019-12-02` 硬守卫。

中信成分的快照 coverage 从 `2019-12-02` 起算，请求早于该窗口会命中缺口报错（离线严格），不会静默取空。

旧 datacenter `sw_level1_cons` 按年入库天数（仅作历史对照）：

| 年 | 有成分的交易日 | 该年交易日总数 |
|---|---|---|
| 2020 | **7** | ~242 |
| 2021 | **1** | ~243 |
| 2022 | 119（**08 月起才连续**） | 242 |
| 2023 起 | 242 | 242 |

后果：任何用 **`diffusion` / `diffusion_rrg`** 且窗口早于 2022-08 的申万回测，扩散指标是 NaN → 信号恒 False → **策略全程空仓**，而绩效表看起来只是"回撤很小"。

`quadrant` 信号不受影响（只用行业指数，不碰成分）。

中信侧不能按旧 WindDB 的 99.9% 覆盖结论使用：当前 PG `zx_index_member` 在
2015-06-30 仅 1,777 只、约 64%，所以扩散类历史窗口必须遵守上述守卫。

### ② warm-up 长度不够会静默全 NaN

| 指标 | warm-up 行数 | 默认值 |
|---|---|---|
| `compute_rs_ratio` | `lookback + smooth_window − 1` | 239 |
| `compute_rrg` | `lookback_ratio + lookback_mom + 2×(smooth_window−1)` | **318** |
| `diffusion_*` | `lookback + smooth_window − 1` | 239 |

`fetch_rrg_dataset` **不预取 warm-up**。要让 `start_date` 当天就有 RRG 信号，把 `start_date` 往前挪约 318 个交易日。（`fetch_diffusion_dataset` 会自己前移 240 天，两者不对称。）

### ③ 缓存水位与数据源缺口

`RRGStore.get_membership` 的 coverage 水位现在**逐缺口推进**：取到数据的缺口才扩水位，整段无数据的缺口会 `warnings.warn` 并保持未覆盖，下次仍会尝试。

切换成分数据源后，必须先备份并清空 `sw_membership` / `zx_membership` 及各自
coverage。否则已有 coverage 会让 store 直接命中旧口径数据，reader 虽已切到 PG，
结果仍可能是旧源或新旧混合，且不会报错。具体 SQL 见[中信行业接入说明 §5](中信行业接入说明_20260828.md#5-duckdb-缓存迁移)。

**看到这条告警不要忽略**——它说明上游数据源在该区间确实没有数据，不是缓存问题：

```
zx 成分取数在以下区间**未返回任何数据**：[(2019-12-02, 2020-01-06)]
```

## 7. 结论边界（引用本项目数字前必读）

**这套代码是干净的，结论是弱的。** 两者要分开看。

| 层 | 结论 | 证据强度 |
|---|---|---|
| 行业指数层 · 象限类 | 中信略优于申万（16 格中 12 格占优，平均 +0.078 夏普） | **中**：有 2015-2022 真样本外 |
| 行业指数层 · 扩散类 | 中信单侧跑通（夏普 0.36/0.42） | **弱**：SW 对照臂因成分缺失无效，无法并列比较 |
| ETF 层 | 中信领先，但 85–91% 的超额来自 2025-07 之后 | **弱**：单窗口、单年份主导 |

**四个已修复的缺陷**（修复前它们都会静默给出错的数字）：

1. 暴露矩阵分母用「已披露持仓 mkv」而非基金净值 → 72% 权重顶到 1.0，LP 最优面退化
2. LP 数值残渣被当真实成交计费 → 12934 笔 vs 顶点解 41 笔
3. 候选池混入 128 只港股 ETF → 拿不到 A 股行业暴露
4. 缓存空返回推进水位 → 掩盖数据源缺口

**仍未解决的边界**：中信成分表的 `ENTRY_DT` / `REMOVE_DT` 是**生效日不是公告日**，表内无公告日字段。按生效日做 PIT，若存在追溯性重分类会有前视。该风险与原 PG 源同级，换源未改变其量级。

## 8. 排错

| 症状 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: tushare/duckdb/vectorbt` | 用了 uv 环境 | 换 `/opt/miniconda3/bin/python` |
| `ModuleNotFoundError: DataFeed` | 没设 PYTHONPATH | `export PYTHONPATH=$HOME/workspace` |
| `ModuleNotFoundError: src` | 没 cd 到项目根 | `cd C-择时类/相对旋转图RRG行业轮动` |
| 信号全 False | warm-up 不足，或成分数据缺失 | 查 §6 ① 和 ② |
| `compute_rs` 缺日 ffill 告警 | 行业指数取数或 pivot 有问题 | **不要忽略**，查取数 |
| notebook 提交后超 100MB | plotly widget 状态存进了 `metadata.widgets` | 提交前剥离该字段（体积不在 outputs 里） |
| `OfflineDataError`：快照缺数据 | `data/etf_rrg.duckdb` 不完整或时间窗越界 | 从百度网盘下载完整快照放到 `data/`（见 `data/说明.md`） |
| `ValueError: No objects to concatenate` | 给 qlib 传了退市股的代码列表 | 用 `QlibProvider("ashares")` 时点池 |
